# YUGA_testing

[![CI](https://github.com/Udbhav7002/YUGA_testing/actions/workflows/ci.yml/badge.svg?style=flat)](https://github.com/Udbhav7002/YUGA_testing/actions/workflows/ci.yml)

Companion demo target for **[YUGA · CodeGhost](https://github.com/Udbhav7002/YUGA)** —
a deliberately fragile FastAPI service whose crashes feed the CodeGhost pipeline:
production crash in → verified fix + pull request out.

## The app

A mock "YUGA Platform" room-booking API (`main.py`) with the CodeGhost crash
interceptor (`middleware.py`) installed: every unhandled exception is scrubbed
by Presidio, signed (HMAC-SHA256), and shipped to the orchestrator.
`apps/auth_service/` holds a second mock service; `api/index.py` + `vercel.json`
deploy it to Vercel.

## Demo scenario

1. `GET /rooms/huddle-0/occupancy` — the rehearsed demo bug: the Huddle Room
   was provisioned with `capacity=0` (bad config row), so the occupancy
   calculation divided by zero → HTTP 500. **This bug is already fixed** —
   CodeGhost-generated fixes were merged from the `codeghost/agent-fixes`
   branch (PR #15) and the endpoint now guards zero capacity — but the
   history shows the full journey: crash in, test, fix, pull request out.
2. The orchestrator generates a failing pytest → proves it **RED** in an
   isolated Docker sandbox → generates a fix → proves it **GREEN** in the
   same sandbox → opens a pull request with both raw outputs attached.
3. Crashes that still fire the pipeline today: an unknown room id
   (`GET /rooms/ghost/occupancy`) raises an unhandled `KeyError` → HTTP 500.
4. `GET /explode` — crash message carrying a fake API key + admin email;
   Microsoft Presidio scrubs both to `<SCRUBBED>` before data leaves the
   process.

## Run it

```bash
pip install -r requirements.txt
uvicorn main:app --port 8003
```

| Method | Path | Behaviour |
|---|---|---|
| GET | `/` | demo dashboard UI (`static/index.html`) |
| GET | `/health` | liveness probe |
| GET | `/rooms` | list rooms |
| GET | `/rooms/{room_id}/occupancy` | occupancy %; unknown id → unhandled `KeyError` → 500 |
| POST | `/book` | book a room (404 unknown room, 409 full) |
| GET | `/explode` | unhandled crash with fake credentials — Presidio scrubbing demo |

To feed crashes to a running CodeGhost orchestrator, set the environment the
interceptor reads (without `CODEGHOST_URL`, reporting is disabled):

```bash
export CODEGHOST_URL="http://127.0.0.1:8002/crash?t=<tenant id>"
export CODEGHOST_SHARED_SECRET="<tenant secret>"
```

Scrubbing uses Microsoft Presidio (`presidio-analyzer` is commented out of
`requirements.txt` — too heavy for serverless — so it degrades to a no-op
without it). The regression tests in `tests/` were generated by CodeGhost
pipeline runs: `pip install pytest && pytest tests/`.

Human stays in the loop — merging the fix is one click.
